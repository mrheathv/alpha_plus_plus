# The Alpha++ Field Manual

The player-facing guide — how a block grows, what every gate wants, and what
each mistake costs. `index.html` is the whole page; it is published as a
private Artifact on claude.ai and this is its source.

**Every figure in it is read from this codebase**, not estimated: costs and
footprints from `ZoneType`, thresholds from `Unlocks` and `Milestone`, the
density gates from `CitySimulator`, catchments from `Transit` and
`ServiceCoverage`, hazard rates from `CityHazards`, and the measured results
from the playtest harness rather than from a guess.

That is also its weakness. **It is a second copy of those facts and it
drifts** — six claims in it were falsified within ninety minutes of writing,
by ranks and land ownership landing. Treat a change to `ZoneType`,
`Unlocks`, `Milestone`, `OverlayMode` or any balance constant as a reason to
check this page.

## The images

They are **not** in the repository. They are build output, regenerated by
`GuideFiguresTests` and `CityPortraitTests` into `build/`, which is
gitignored — the app icon is the one raster this project commits, and only
because the app needs it to compile.

To rebuild them:

```sh
xcodebuild -project AlphaPlusPlus.xcodeproj -scheme AlphaPlusPlus \
           -configuration Debug -derivedDataPath ./build test \
           -only-testing:AlphaPlusPlusTests/GuideFiguresTests

TEST_RUNNER_PORTRAIT_CITY=Riverrun xcodebuild \
           -project AlphaPlusPlus.xcodeproj -scheme AlphaPlusPlus \
           -configuration Debug -derivedDataPath ./build test \
           -only-testing:AlphaPlusPlusTests/CityPortraitTests
```

The portraits need a minted save; `CityMinterTests` with
`TEST_RUNNER_MINT_CITIES=1` writes them, and `TEST_RUNNER_MINT_ONLY=Riverrun`
cuts one recipe rather than all eight.

Then, per `img/` path in the page:

| published path | from |
| --- | --- |
| `img/hero.jpg` | `build/ContactSheet/guide-cover-70.png` |
| `img/map.jpg` | `build/Portraits/Riverrun-wide.png` |
| `img/close.jpg` | `build/Portraits/Riverrun-close.png` |
| `img/terrain.jpg` | `build/Portraits/Harbour-wide.png` |
| `img/growth.png` · `zones` · `services` · `views` · `marks` · `transit` · `transit-steps` | `build/ContactSheet/guide-<name>.png` |
| `img/landmarks.png` | `build/ContactSheet/landmarks.png` |

Scaled to 1600px on the long edge; the four photographic ones go to JPEG at
quality 88, which is visually identical and about eight times smaller. The
flat-background sheets stay PNG so their captions stay sharp.

## The brand system

The visual identity — tokens, wordmark rules, the licensing problem with the
title screen's face — lives in its own Design System artifact rather than
here. Deliberately: that page is editable in place by people, so a copy in
this repository would be exactly the second source of truth this file warns
about. The Swift stays upstream of both.
